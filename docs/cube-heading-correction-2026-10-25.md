# Cube/QGC heading correction — October 25, 2026

User explicitly requested that accepted GPS/DVL heading alignment correct the heading sent to Cube/QGC, with no added checks. Previous code applied the accepted rotation only to Jetson's geographic map. This change deliberately updates the local frame at the existing stopped-alignment acceptance; it supersedes the earlier promise that all north corrections leave Cube's yaw reference unchanged.

On accepted alignment, `ContinuousEstimator.correct_heading` rotates yaw, horizontal velocity, covariance and retained local history about the current vehicle position. That position remains fixed at the handoff. The accumulated yaw offset is applied to subsequent VN measurements so the correction persists. GPS registration is rebuilt in the corrected local frame, avoiding a second application of the north rotation. Pose, covariance and body velocity sent in ODOMETRY stay consistent. The bridge increments its ODOMETRY reset counter once for the reference change. GUIDED mission caches rotate their position and heading targets using the same event, once per revision.

This sends corrected external-navigation yaw into Cube's existing ExternalNav yaw source. It does not fabricate QGC telemetry, write a compass calibration, change flight-controller parameters, reset geographic origin, arm, clear control inhibits or issue motion. Actual Cube yaw convergence and the resulting QGC display have not been physically demonstrated. ArduPilot retains its normal external-yaw fusion behavior; a reset counter must not be described as proof of an instantaneous EKF yaw reset. Subsequent small map-only course refinements retain their previous behavior; this change applies the accepted initial north alignment to Cube yaw.

No new mission abort, readiness or confidence conditions were introduced. The previously removed absolute 5 m position-sigma abort remains absent. Existing alignment acceptance is reused. The initial leg remains 10 m and the temporary 5 m waypoint cap remains removed.

39 focused tests passed both locally and onboard. They cover signed/cardinal heading rotations, unchanged current position, unchanged body-relative velocity, covariance transformation, VN-offset persistence, GUIDED cache rotation/deduplication, corrected ODOMETRY yaw/reset-counter delivery, GPS-fusion gating and DVL dropout prediction. These are software and mocked-transport results, not a physical alignment certification. Non-waypoint mission handling of a frame change was not newly validated.
